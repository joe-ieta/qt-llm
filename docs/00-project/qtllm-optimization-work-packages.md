# qt-llm 基础能力优化开发工作包

- 文档版本：1.0
- 编制日期：2026-09-13
- 状态：实施中；QTL-00、QTL-01 已完成
- 上位方案：[qt-llm 通用 LLM 基础能力优化方案](./llm-foundation-optimization-plan.md)
- 适用仓库：E:\CodexDev\qt-llm

本文把已确认的优化方案拆分为可独立设计、开发、评审和验收的工作包。工作包编号可直接用于 Issue、分支、提交说明和验收记录。CoReader 迁移任务见 [CoReader 集成改造开发工作包](./coreader-integration-work-packages.md)。

## 1. 执行规则

1. 一个工作包只解决一个主要问题，可单独建立分支和评审。
2. 依赖完成后才能使用其公共契约；没有依赖关系的工作包可以并行。
3. 保留现有公开接口，新接口先通过兼容适配接入现有实现。
4. 除纯基线任务外，每个包同时交付实现、针对性测试和受影响文档。
5. 验收记录区分通过、失败、跳过和未覆盖。
6. 公共类型或行为变化必须说明源码兼容、行为兼容和 ABI 影响。
7. 不把 CoReader 的任务、工作流、文档、翻译或阅读业务语义加入 qt-llm。

## 3. 详细工作包

### QTL-00 公共契约与兼容基线

状态：已完成。交付物见 [qt-llm 公共契约与兼容基线](qtllm-public-contract-baseline.md)。

目标：在实现改造前冻结可观察基线，确定必须保留的接口和行为。

范围与交付：

- 盘点 RuntimeFacade、QtLLMClient、ConversationClient、ToolEnabledChatEntry 和公共类型。
- 记录信号、错误、配置默认值、存储路径、ID 与内置工具行为。
- 建立 Qt5、Qt6 及代表性宿主消费矩阵。
- 形成兼容基线、接口清单、行为测试清单和弃用规则。

验收：清单可追溯到公共头文件；关键行为有测试位置或明确标为未覆盖；CoReader 当前使用面全部映射。

边界：不修改运行实现，不提前锁定尚未评审的新类型名称。

依赖：无。完成后 QTL-01、QTL-02、QTL-03 可并行。

### QTL-01 CMake 发布与消费出口

状态：已完成。集成说明与验证矩阵见 [CMake 集成 qt-llm](../30-development/cmake-consumption.md)。

目标：让外部项目通过稳定 target 使用 qt-llm，不再编译内部源码。

范围与交付：

- 支持源码子项目和安装后配置包查找两种模式。
- 导出正式命名空间 target、版本、传递依赖和公共头文件。
- 子项目模式不覆盖宿主输出目录、编译选项和 Qt 主版本，默认关闭应用与测试。
- 建立 Qt5、Qt6 独立最小消费工程和集成说明。

验收：两种模式均能构建最小调用；Qt5、Qt6 分别记录结果；旧仓库内 target 仍可使用。

边界：本包不拆分全部库目标，不改变模型调用行为。

依赖：QTL-00。可与 QTL-02、QTL-03 并行。

### QTL-02 请求生命周期治理

状态：已完成。生命周期、错误、重试与兼容规则见 [请求生命周期契约](../30-development/request-lifecycle.md)。

目标：建立可靠、可测试的单请求执行契约。

范围与交付：

- 确保每个逻辑请求只有成功、失败或取消中的一个终态。
- 建立稳定错误分类，保留底层诊断、可重试性和可选 HTTP 状态。
- 使取消覆盖活动传输、重试退避和待启动请求。
- 定义流式已经输出内容后的重试及 attempt/reset 语义。
- 区分取消请求、取消完成和不可中断执行。

验收：工具失败不再同时报告错误和完成；退避期间取消不会重新发起请求；不同重试尝试的流式内容不会混合；旧错误信号保留兼容转接。

边界：只处理模型请求级重试，不实现工作流步骤重试。

依赖：QTL-00。为 QTL-04、QTL-07 提供基础。

### QTL-03 基础事件与诊断解耦

状态：已完成。事件接口、接收端和诊断启用规则见 [基础事件与诊断接入](../30-development/event-diagnostics.md)。

目标：提供稳定基础事件，并允许核心在不启用 SQLite 和 ToolsInside 时运行。

范围与交付：

- 定义请求、重试、增量、工具与终态事件及关联标识。
- 提供可注入事件接收端和无操作默认实现。
- 将 ToolsInside、文件日志和测试记录器改为可选接收端。
- 明确载荷记录、脱敏、内容落盘和线程投递策略。

验收：最小调用不隐式建立诊断数据库；启用适配器后事件顺序和关联正确；旧诊断功能有兼容配置。

边界：不定义 task、step、workflow，不接管宿主审计数据库。

依赖：QTL-00。可与 QTL-01、QTL-02 并行，为 QTL-04、QTL-06、QTL-07 提供基础。

### QTL-04 统一请求模型与请求句柄

状态：已完成。结构化消息、独立异步请求句柄、请求级状态与结果归属已落地；旧同步门面继续兼容。

目标：让流式、非流式、单轮和多轮调用共用一套执行机制。

范围与交付：

- 主要门面接受结构化消息列表，并兼容 systemPrompt/userPrompt 便利字段。
- 提供独立请求句柄、请求 ID、状态、增量、取消和最终结果。
- 阻塞接口复用异步机制，不建立第二条传输路径。
- 收敛 RuntimeFacade 与 QtLLMClient 的配置、结果和错误传播。
- 明确对象所有权、回调线程、销毁和关闭等待规则。

验收：流式与非流式结果一致；并行请求事件可正确归属；旧调用经兼容适配执行；UI 主线程不依赖嵌套事件循环。

边界：不内置宿主历史库，不自动检索文档或生成业务提示词。

依赖：QTL-02、QTL-03。完成后 QTL-05、QTL-06、QTL-08 可并行。

### QTL-05 结构化输出与模型能力查询

状态：已完成。文本、JSON、受控 JSON Schema、终态校验、能力证据和受控供应商映射已落地。

目标：提供业务无关的输出约束、校验和调用前能力判断。

范围与交付：

- 支持文本、JSON 和受控 JSON Schema 输出要求。
- 返回原始文本、解析结果、Schema 校验结果和明确失败类别。
- 区分原生约束、提示词约束、不支持和未知。
- 提供流式预览与最终有效结果的边界。
- 建立能力快照，标明提供方默认、模型配置、运行探测或未知来源。
- 自动修复默认关闭；可选修复受次数、预算和事件约束。

验收：语法错误、Schema 不匹配与调用失败可区分；未知不误报为支持；不支持的约束不静默降级；提供方映射有受控测试。

边界：不判断业务结果质量，不存放翻译或阅读 Schema，不建设模型市场。

依赖：QTL-04。可与 QTL-06、QTL-08 并行。

### QTL-06 工具注册与双执行模式

状态：已完成。外部执行批次、三态授权、限额结果、调用配对、显式并发、活动取消、超时状态与幂等重试策略均已落地。

目标：让轻量应用和已有 Agent Runtime 的宿主使用同一工具契约。

范围与交付：

- 用公开注册接口替代内部符号覆盖式工具定制。
- 保留库内有限工具循环，增加由宿主处理的外部执行模式。
- 提供允许、拒绝、等待决定的授权接口。
- 完善参数校验、超限结果、取消、线程要求、超时和真实并发调度。
- 明确幂等性和副作用工具重试策略。
- 保持 MCP 客户端消费与 MCP Server 发布的能力边界。

验收：两种模式保持调用与结果配对；宿主无需重定义内部符号；拒绝、等待、超限与不可取消状态可观察；并发参数与实际行为一致。

边界：不实现业务工具、工作流 DAG 或 MCP Server。

依赖：QTL-03、QTL-04。可与 QTL-05、QTL-08 并行。

### QTL-07 本地模型运行实例管理

状态：已完成。显式运行管理服务、实例身份、共享租约、端口排队、所有权、分阶段超时与取消均已落地；同步门面和异步请求句柄已接入共享服务，同时保留直接使用 `QtLlmClient` 的既有私有运行时行为。

目标：由 qt-llm 协调托管 llama.cpp 的实例、共享和所有权。

范围与交付：

- 提供由宿主显式持有的运行管理服务。
- 区分连接外部服务和启动库拥有的服务。
- 按模型、端口和启动参数区分实例，协调并发启动与排队。
- 区分排队、启动、请求和总超时。
- 定义单请求取消、调用者释放和共享服务关闭行为。

验收：并发调用不重复启动同一实例；一个调用者退出不影响其他使用者；外部进程不被库关闭；取消和各阶段超时明确。

边界：不提供模型安装 UI，不替宿主决定模型来源和部署策略。

依赖：QTL-02、QTL-03。可与 QTL-04 并行，最终接入统一请求路径。

### QTL-08 会话与上下文预算

状态：已完成。统一消息窗口、system 与最近完整轮次保留、工具调用组原子裁剪、输出预算、估算/精确 token 计数、明确超限结果、宿主自管历史和旧快照兼容均已落地。

目标：提供通用消息窗口管理，同时允许宿主完全自管会话和历史。

范围与交付：

- ConversationClient 使用统一请求模型。
- 提供 system、最近完整轮次和完整工具配对的保留策略。
- 为输出预留预算，区分精确 token 和估算结果。
- 必保留内容超限时返回明确错误。
- 支持无存储、宿主提供历史和可选仓库适配。

验收：裁剪不破坏工具配对；宿主自管历史无需启用 qt-llm 数据库；旧会话快照可读取或有明确迁移器。

边界：不实现文档检索、长期记忆和自动 RAG；自动摘要不属于首批范围。

依赖：QTL-04。可与 QTL-05、QTL-06 并行。

### QTL-09 库目标与可选组件分层

目标：在公共契约稳定后降低最小集成依赖，保留兼容聚合 target。

范围与交付：

- 形成轻量核心、会话、工具/MCP、本地运行和诊断适配器的目标边界。
- 保留 qtllm::qtllm 聚合 target。
- 核心不强制依赖 Qt Widgets、Qt Sql 或应用资源。
- 明确静态/共享构建、符号导出和组件化安装配置。

验收：最小核心不链接无关 Qt 模块；聚合 target 保持既有能力；可选组件能被配置包发现。

边界：不为目录整齐而拆库，不在公共契约稳定前改变二进制布局。

依赖：QTL-01、QTL-03、QTL-06、QTL-07；同时确认 QTL-04 至 QTL-08 的公共类型归属。

### QTL-10 示例、文档与发布验收

目标：为公共能力提供最短集成路径，并形成可供外部项目采用的候选版本。

范围与交付：

- 提供无 UI 调用、流式取消、结构化输出、宿主历史、宿主工具、本地模型和事件接收示例。
- 将现有示例迁移到公开接口。
- 更新架构、集成、配置、API、故障处理和发布文档。
- 执行 Qt5、Qt6 构建、受控运行和安装消费矩阵。
- 使用 CoReader 跨项目结果形成兼容报告、已知限制与回退说明。

验收：示例只使用公共头文件和正式 target；能力状态标记准确；矩阵结果可追溯；跳过项不计为通过；CoReader 代表性路径通过。

边界：不以示例或验收名义引入计划外能力，不修改 CoReader 业务行为换取通过。

依赖：文档和示例持续跟随对应包；候选发布依赖 QTL-01 至 QTL-09 的本轮范围及 CoReader COR-08。

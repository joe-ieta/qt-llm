# qt-llm 通用 LLM 基础能力优化方案

- 文档版本：1.0
- 编制日期：2026-09-13
- 状态：qt-llm 侧 QTL-00 至 QTL-10 已全部完成。当前统计见 [qt-llm 优化工作包完成状态](./qtllm-work-package-status.md)；CoReader 迁移仍按独立计划推进。
- 依据：qt-llm 与 CoReader 当前工作区源码、构建文件及集成文档的静态分析。
- 范围：基础库、公共接口、配套工具、文档，以及 CoReader 的后续接入迁移。
- 约束：保持现有代码能力与对外接口兼容，不将宿主业务逻辑纳入基础库。

本文保留最初的目标设计、问题分析和分阶段实施依据。qt-llm 侧工作包已经完成，当前接口和验证结论以集成手册、API 索引及发布验证文档为准；真实模型和真实 MCP 服务仍只在具备外部运行环境时验证。

## 1. 目标与原则

qt-llm 定位为**面向 Qt/C++ 应用的可嵌入 LLM 能力库**，统一提供模型调用、结构化输出、流式交互、工具执行和本地模型管理。普通宿主通过少量稳定接口完成接入，高级宿主可以替换必要的执行与存储适配器。

本轮优化以三个结果为目标：

1. 更容易集成：链接正式库目标，通过统一入口调用，无需编译内部源码或维护请求生命周期。
2. 更可靠可控：请求有明确状态、唯一终态、结构化错误和覆盖全过程的取消语义。
3. 更通用可扩展：基础机制由 qt-llm 提供，业务提示词、流程、数据模型和产品交互由宿主拥有。

设计原则：

- 优先完善已有入口，不建立另一套职责相同的客户端、工具框架或事件体系。
- 普通调用保持简单，会话、工具、存储和诊断按需启用。
- 使用 Qt 原生异步机制，明确线程、对象所有权及退出行为。
- 增量增加接口或通过兼容转接升级，不强制外部项目同步迁移。
- 功能增强和模块拆分分步实施，每一步都有独立验收结果。
- 保持 Qt5、Qt6 支持方向，分别验证、分别构建产物。

## 2. 现状与集成问题

### 2.1 已有基础

qt-llm 已有 `QtLLMClient`、`RuntimeFacade`、`ConversationClient`、工具与 MCP 扩展、本地 llama.cpp 管理、日志和 ToolsInside 追踪等实现。主要问题是高级入口覆盖不足、执行契约不一致，以及宿主需要了解内部实现。本方案不要求重新建设全部已有能力。

| 能力 | 当前状态 | 优化重点 |
| --- | --- | --- |
| 模型与流式调用 | 已有底层和宿主入口 | 共用执行机制，统一结果和生命周期 |
| 消息与会话 | 底层支持消息列表，会话层支持历史和快照 | 高级门面接收消息列表，允许宿主自管历史 |
| 结构化输出 | 已有 JSON 类型和工具解析，公共请求尚未形成通用输出约束 | 输出格式、Schema 校验和能力声明 |
| 工具与 MCP | 已有执行器、调用封装、客户端和服务器配置注册 | 异步、取消、授权、外部执行模式 |
| 本地模型 | 已有发现、可用性检查与托管运行 | 实例复用、资源协调、状态分离 |
| 日志与追踪 | 已有记录、存储和查看工具 | 可注入接收端，解除存储强耦合 |
| CMake | 已提供五个组件目标与 `QtLlm::QtLlm` 兼容聚合目标 | Qt5/Qt6、STATIC/SHARED、安装包和源码消费均已验证 |

### 2.2 CoReader 实际集成成本

| 编号 | 静态阅读现象 | 影响 | 优化方向 |
| --- | --- | --- | --- |
| O1 | 桥接工程手工列举 qt-llm 内部源码编译 | 依赖目录布局，升级易漏依赖 | 正式 CMake target 与安装出口 |
| O2 | 流式走 `QtLLMClient`，非流式走 `RuntimeFacade` | 两套配置、取消、错误和观察处理 | 统一执行入口 |
| O3 | BotChat 将历史角色与内容拼成一段文本 | 高级路径没有保留结构化消息角色 | 门面接收消息列表 |
| O4 | 翻译和阅读辅助自行要求、解析并判断 JSON | 通用结果处理重复，失败语义分散 | 结构化输出支持 |
| O5 | 分别映射 `LlmConfig` 与 `RuntimeProfile` | 字段重复，配置容易漂移 | 统一公共配置与内部转换 |
| O6 | 桥接层为本地 llama.cpp 加锁串行化调用 | 宿主承担基础运行协调 | 显式运行实例管理 |
| O7 | 工具 shim 实现 qt-llm 命名空间内的函数 | 扩展依赖内部符号，标准链接存在冲突风险 | 注册式扩展、可选内置工具 |
| O8 | 观察器将模型事件映射到任务执行台账 | 表明基础事件与编排语义可以分离 | 保留宿主映射，统一基础事件 |

源码位置见第 11 节。CoReader 的业务适配接口有保留价值，目标是使其变薄，而不是要求业务代码直接依赖 qt-llm。

## 3. 架构边界

### 3.1 三方职责

| 领域 | qt-llm | 独立 Agent Runtime | CoReader 业务及应用层 |
| --- | --- | --- | --- |
| 模型调用 | 协议、传输、流式、请求取消与重试 | 协调步骤执行 | 提示词和业务调用目的 |
| 结构化输出 | 解析、格式约束、Schema 校验 | 传递结果，协调失败处理 | 定义 Schema，判断业务有效性 |
| 上下文 | 消息角色、通用预算与裁剪 | 组织步骤输入输出 | 选择文档、段落、证据和历史 |
| 工具 | 注册、调用、结果和有限工具循环 | 工作流编排、步骤重试和恢复 | 实现业务工具并决定授权规则 |
| 本地模型 | 发现、启动、复用、健康与资源协调 | 消费基础运行状态 | 设置、部署位置和产品体验 |
| 可观测性 | 请求与工具事件、用量、耗时和关联标识 | 任务、步骤、DAG 状态及执行台账 | 产品审计与展示 |
| 存储 | 可选通用会话、诊断适配器 | 工作流状态及恢复数据 | 业务数据库、文档资产和产品历史 |

qt-llm 的执行单位是“模型请求”和“工具调用”。宿主的 task、step、workflow、document 等标识可以作为不透明关联信息传入，基础库不解释其结构和含义。

### 3.2 本轮不纳入的内容

- 任务规划、DAG、工作流目录、步骤调度、工作流恢复和业务级重试。
- 文档转 Markdown、文档切块、结构锚点、语义单元、证据选择和引用定位。
- 翻译与解释的业务提示词、语言路由、领域 Schema 和业务兜底。
- 文档资产库、报告生成、BotChat 历史表结构和编辑重发规则。
- 长期记忆系统、完整 RAG 平台，以及缺少具体集成需求的通用任务或插件平台。

CoReader 早期提案中的 task、step、plan 通用封装本轮不下沉。即使不含阅读业务，它们仍会与独立 Agent Runtime 的编排职责重叠。

## 4. 目标对外接口

### 4.1 主要入口与兼容层

普通宿主继续优先使用 `RuntimeFacade`，通过增量增强覆盖结构化消息、请求句柄、统一结果和事件。

`ConversationClient` 保留会话便利能力，`ToolEnabledChatEntry` 保留工具接入便利能力，两者逐步共用统一执行机制。`QtLLMClient` 保留为兼容及高级扩展入口，不另建长期并行的模型传输链路。

### 4.2 最小公共契约

以下为目标职责，不是已发布 API：

| 对象或入口 | 内容与职责 |
| --- | --- |
| 模型调用门面 | 配置连接、提交请求、查询模型能力和本地运行状态 |
| 请求 | 消息列表、模型选择、生成参数、输出约束、工具选择、关联信息 |
| 请求句柄 | 请求 ID、状态、增量事件、取消与最终结果 |
| 结果 | 正文、结构化数据、工具调用、结束原因、用量、结构化错误和必要的部分输出 |
| 工具注册入口 | 宿主执行器、MCP 接入、授权策略和执行模式 |
| 可选会话层 | 历史组织、上下文预算、快照及存储适配 |
| 事件接收端 | 消费基础事件，不强制指定数据库 |

通用控制项使用明确字段，`metadata` 仅用于宿主关联和必要扩展，不能成为隐藏控制协议。凭据、连接配置和本地运行选项不重复放入消息对象。

能力查询区分支持、不支持和未知，注明信息来自提供方声明、模型配置还是实测。不能仅凭提供方名称认定具体模型支持某种参数、工具或结构化输出。

### 4.3 生命周期与线程

1. 异步为主路径，阻塞接口复用同一机制，仅作为便利封装，不用于阻塞 UI 主线程。
2. 每次调用具有独立句柄，增量、错误、取消和完成均能准确归属。
3. 每个请求恰好产生一个最终结果，成功、失败和取消互斥；拒绝受理也有明确归属。
4. 流式与非流式使用相同结果结构，流式额外提供过程事件。
5. 取消覆盖排队、本地启动、传输、重试退避和工具执行；不可中断操作必须明确报告支持范围。
6. 取消请求与取消完成分开表达，不能把后台仍在执行的工作描述为已经停止。
7. 明确信号回调线程、对象所有权、销毁行为和关闭等待规则；支持跨线程安全投递取消，不暗示全部方法线程安全。
8. 逻辑请求、重试尝试和工具轮次具有可追踪关联，不让一次调用产生多个无法关联的结果。

### 4.4 配置与错误

公共配置按职责区分连接与凭据、请求默认值、本地运行选项；探测结果和实际启动计划通过状态对象返回。逐步减少 `RuntimeProfile` 同时承载输入和运行结果的情况，旧字段通过兼容映射保留。

错误至少表达稳定错误码、原始诊断、可重试性和可选 HTTP 状态。区分配置、鉴权、限流、网络、超时、取消、解析、Schema 和工具执行错误。用户可见文案由宿主负责。

不能只以“正文非空”判断结果有效性：工具调用、结构化结果、部分输出和文本有不同语义。usage 缺失表示未知，不能自动记为零。

## 5. 能力增强设计

### 5.1 结构化输出

- 支持文本、JSON 和 JSON Schema 输出要求，由宿主提供 Schema。
- 区分原生约束、提示词约束和不支持，不能静默宣称等价支持。
- 区分语法解析、Schema 校验和业务正确性，最后一项属于宿主。
- 保留原始输出与校验信息，公布支持的 Schema 范围，对不支持的约束显式报错。
- 流式片段可以预览，完整结束并通过校验后才标记为有效结果。
- 自动修复或额外模型调用默认关闭；启用时限制次数、计入预算并发出事件。

CoReader 的语言路由、翻译和解释复用该机制，字段定义、语言判断和业务回退保持原位。

### 5.2 消息与上下文

高级入口接受消息列表，保留消息角色和工具关联。宿主已有历史库时可以直接提供消息，无需启用 qt-llm 会话存储。

第一批预算策略保留 system、最近完整轮次和完整工具调用配对，同时预留输出空间。Token 无法精确计算时标记为估算。必保留内容超出预算时返回明确错误，不能静默删除。

自动摘要后置，不把文档检索、切块、证据挑选或长期记忆作为会话入口的隐式行为。

### 5.3 工具与 MCP

复用现有工具请求/结果、`IToolExecutor`、注册器和 MCP 客户端，支持两种方式：

| 方式 | 行为 | 场景 |
| --- | --- | --- |
| 库内有限工具循环 | 在明确预算内执行模型、工具和后续模型调用 | 轻量聊天与简单工具应用 |
| 外部执行 | 返回工具调用，由宿主批准、执行并提交对应结果 | 已有 Agent Runtime 或自定义执行系统 |

两种方式共享定义、关联 ID 和结果格式。工具回传由协议适配器保持调用与结果配对，不能一律降格为普通用户提示词。

授权应明确允许、拒绝或等待决定；仅供观察的 `beforeExecute` 不等于授权接口。业务规则与确认 UI 由宿主负责。

完善参数校验、取消、超时、并发上限及超限结果。幂等性字段不代表已经保证幂等，有副作用工具不能默认自动重试。调度遵守执行器线程要求，不能把全部宿主回调直接送入工作线程。

内置工具通过配置注册，避免宿主重定义内部符号。迁移时保留兼容默认配置，再显式切换选用方式。

MCP 客户端消费、外部服务器配置注册、将宿主能力发布为 MCP Server 是不同能力。本轮完善已有客户端；服务端发布按明确需求另设可选扩展，不能宣称现有注册接口已经提供该能力。

### 5.4 本地模型生命周期

提供由宿主显式持有、可共享的运行管理服务，区分连接已有服务与启动库管理服务。

- 按实例协调发现、启动、健康检查、排队和复用。
- 按模型、端口及启动配置区分实例，不以单一全局锁覆盖全部模型请求。
- 区分单请求取消与共享服务关闭，一个调用者退出不应停止其他调用者的服务。
- 只关闭明确拥有的进程，不停止外部已有服务。
- 区分排队、启动、请求超时及总预算，明确等待阶段。
- 分离高层运行意图与底层诊断，宿主不维护 GPU、线程和端口协调细节。

### 5.5 事件与诊断

统一请求与工具事件，覆盖受理、启动、发送、增量、重试、工具执行和终态，包含请求 ID、trace 关联、时间、尝试次数及必要用量。

通过可注入接收端对接宿主日志、ToolsInside 或测试记录器。核心不强制初始化 SQLite、切换全局工作目录或写出完整提示词。新轻量模式默认不新增内容落盘，完整载荷记录需显式启用并应用记录范围和脱敏策略；旧行为通过兼容配置迁移。

CoReader 观察器继续将基础事件映射到任务和步骤台账，qt-llm 不拥有 workflow 状态。

## 6. 优先治理的可靠性问题

以下是静态执行路径风险，实施时需形成针对性复现和回归测试，不视为已完成运行验证。

| 编号 | 当前现象 | 目标行为 |
| --- | --- | --- |
| R1 | 工具失败保护先发错误，再发完成信号 | 唯一失败终态，部分输出放入结果 |
| R2 | 重试等待期间无活动 reply，取消直接返回，已安排重试仍可启动 | 取消使待执行重试失效并终结逻辑请求 |
| R3 | 流式部分输出后重试缺少尝试重置契约 | 默认不透明重放；允许重试时提供 attempt/reset 语义 |
| R4 | 工具批处理实际同步循环，并行字段不代表真正并行 | 公布真实范围，执行遵守调度契约 |
| R5 | 工具会话取消返回不支持 | 传递可支持的取消，不可取消时明确报告 |
| R6 | 高级门面将部分底层错误统一为 `request_failed` | 保留分类和诊断，支持宿主决策 |

请求级重试归 qt-llm，工作流步骤重试归 Agent Runtime。二者有可见次数和总预算，避免叠加失控。已产生部分输出或已执行副作用工具的调用，不默认整轮重放。

修正终态属于可观察行为变化，应记录兼容说明，验证宿主没有依赖错误后的完成信号继续执行。

## 7. 工程结构、工具与集成出口

### 7.1 按依赖分层

| 部分 | 内容 |
| --- | --- |
| 轻量核心 | 公共类型、协议、网络、流式、生命周期、错误与事件 |
| 按需扩展 | 会话、工具/MCP、本地模型管理 |
| 存储与诊断适配器 | SQLite、文件记录、ToolsInside |
| 独立应用与示例 | 聊天、ToolStudio、ToolsInside 查看器、MCP 管理器、PDF Agent |

先解除诊断存储强耦合，再按实际依赖拆目标，不一次拆成大量小库。保留 `qtllm::qtllm` 兼容聚合目标。轻量核心不强制依赖 Widgets、Sql 或示例资源。

### 7.2 正式 CMake 出口

- 支持源码子项目引入及安装后配置包查找，消费正式 target。
- 导出依赖和版本，使用稳定的项目命名空间头文件路径，旧路径保留兼容头。
- 子项目模式默认关闭示例和测试，编译特性、输出目录和选项不污染宿主。
- 遵循宿主选择的 Qt 主版本，冲突时报错，不在同一应用混合 Qt5/Qt6。
- 两个 Qt 主版本分别构建包并标明工具链，源码兼容不代表二进制可互换。
- 使用独立消费工程验证安装出口，不只验证仓库内部构建。

### 7.3 工具和示例

示例使用公开入口，不继续示范内部源码拼接或私有组件初始化。ToolStudio 与 MCP 管理器消费公开注册契约，ToolsInside 作为诊断消费者，不成为普通模型调用的必备组件。

提供最小无 UI 调用、流式取消、结构化输出、宿主自管历史、宿主工具和事件接收示例。业务提示词与业务 Agent 保留在独立应用中。

## 8. 兼容与 CoReader 迁移

### 8.1 兼容策略

- 保留公开类名、调用入口、信号和包含路径，优先使用重载、新类型或兼容适配增加能力。
- 保留旧配置读取和必要默认行为，调整时提供显式新策略与迁移说明。
- 不未经说明改变序列化格式、存储路径、ID 格式假设或工具默认集合。
- 区分源码、行为和 ABI 兼容；结构体加字段不保证 ABI，二进制稳定需单独设计版本化边界。
- 本轮不默认删除兼容入口，后续弃用另定版本与迁移安排。

### 8.2 CoReader 迁移顺序

1. 保留 `IQtLlmModelBinding` 与业务调用关系，验证正式 target 替代手工源码编译，同时处理 shim 符号冲突。
2. 桥接层采用统一执行机制，合并流式和非流式配置、错误与取消路径。
3. BotChat 传递结构化消息，保留数据库、文档关联、UI 和编辑重发规则。
4. 翻译与解释声明输出约束，复用解析校验，保留业务 Schema、语言路由和回退。
5. 观察器把统一事件映射到原台账，不迁移任务、步骤和恢复状态。
6. 验证本地运行协调后移除临时串行锁，按实际需求迁移工具注册与执行模式。

各步骤独立回归和回退，不能以迁移 CoReader 为由改变其他宿主接口。

## 9. 分阶段实施与验收

### 9.1 第一阶段：可靠集成

交付：正式 target 和安装出口、兼容头文件策略、终态与错误治理、取消和重试修正、兼容说明。只完成必要依赖解耦，不要求全部模块拆分。

验收条件：

- Qt5、Qt6 分别通过源码引入及安装消费构建，记录确切版本和工具链。
- 既有入口与代表性宿主保持编译可用。
- 重试等待期间取消不再发请求，工具失败无双终态，部分输出后的重试行为明确。
- CoReader 正式链接路径通过验证，不依赖内部源码列表或冲突符号替换。

### 9.2 第二阶段：简化应用调用

交付：门面消息列表、请求句柄、统一配置映射和结果、结构化输出、能力查询、基础事件及 CoReader 桥接迁移。

验收条件：

- 流式与非流式共享机制，结果字段及错误分类一致。
- BotChat 保留消息角色，不靠文本标记模拟多轮协议。
- 翻译与解释可声明 Schema，得到明确的解析和校验状态。
- 宿主可自管历史与诊断存储，无需接受指定数据库。
- 不支持的能力显式返回，不能静默降级后宣称满足约束。

### 9.3 第三阶段：按需增强

交付：工具外部执行与授权、本地运行实例复用、上下文预算、可选存储和诊断适配、配套工具迁移。

验收条件：

- 两种工具模式保持调用与结果关联，超限、拒绝和取消状态明确。
- 共享本地服务生命周期正确，不关闭外部或其他调用者仍使用的服务。
- 宿主无需为普通调用维护 llama.cpp 全局互斥和基础取消轮询。
- 轻量核心可在不启用数据库、Widgets 和工具管理应用时被消费。
- CoReader 原业务数据库和独立工作流继续使用，无业务语义下沉。

本方案不预设版本号或时间承诺，每阶段通过验收后进入下一阶段。第一、二阶段为本轮优先交付价值。

### 9.4 验证矩阵

| 层次 | 重点 |
| --- | --- |
| 公共契约 | 旧接口编译、消息映射、结果、错误、唯一终态与配置兼容 |
| 受控运行 | 假提供方或本地服务验证分片、即时错误、取消竞态、退避和超时 |
| 工具执行 | 参数错误、授权拒绝/等待、超限、取消传播及副作用重试 |
| 本地模型 | 并发启动、实例复用、启动失败、进程所有权、退出和排队取消 |
| 外部集成 | Qt5/Qt6 消费工程、CoReader 桥接、BotChat 和翻译/解释回归 |
| 可选适配器 | 无存储模式不隐式落盘，启用后的路径、脱敏与事件关联正确 |
| 真实模型 | 单独记录模型、提供方、配置、覆盖能力及失败情况 |

通过、跳过和未覆盖分别报告。未配置凭据或未安装某 Qt 环境不计为通过；离线测试不等于真实模型可用；CoReader Qt6 验证也不等于 CoReader 本身已支持 Qt5。

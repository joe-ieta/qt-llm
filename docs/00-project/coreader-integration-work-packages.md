# CoReader 使用 qt-llm 的集成改造开发工作包

- 文档版本：1.0
- 编制日期：2026-09-13
- 状态：迁移任务规划，尚未实施
- 上位方案：[qt-llm 通用 LLM 基础能力优化方案](./llm-foundation-optimization-plan.md)
- 基础库任务：[qt-llm 基础能力优化开发工作包](./qtllm-optimization-work-packages.md)
- 适用仓库：E:\CodexDev\CoReader

本文将 CoReader 对新版 qt-llm 的采用过程拆分为可独立开发和回归的工作包。文档存放在 qt-llm 仓库，用于协调两个项目；实施时应在 CoReader 仓库建立对应任务，并更新其活动架构文档。

## 1. 迁移原则

1. 保留 IQtLlmModelBinding 作为业务与基础库之间的防腐层，逐步减少其内部重复机制。
2. 每次只迁移一个集成面，使翻译、阅读辅助、BotChat 和 Agent Runtime 能分别回归。
3. CoReader 继续拥有业务提示词、业务 Schema、语言路由、历史库、文档关系和工作流状态。
4. 对应 qt-llm 公共契约达到可集成状态后，才开始依赖该契约的迁移包。
5. 临时锁、shim 和兼容映射在替代能力验证后删除，不能提前移除。
6. 每包独立提交代码、测试、文档和回退说明，不把多个业务路径绑成一次大迁移。
7. CoReader 当前 Qt6 验证不代表 CoReader 已支持 Qt5；Qt5 属于 qt-llm 的独立验证范围。

## 3. 详细工作包

### COR-00 集成基线与迁移护栏

目标：记录 CoReader 当前依赖面和可观察行为，为各迁移包提供回归基线。

范围与交付：

- 盘点 qtllm-bridge、翻译、阅读辅助、BotChat、本地 llama.cpp、工具 shim 和调用观察器。
- 记录配置字段、错误映射、流式事件、取消、重试和模型结果行为。
- 固化 IQtLlmModelBinding 及相关 DTO 契约测试。
- 建立代表性业务路径、环境依赖矩阵和回退原则。

验收：全部直接包含 qt-llm 头文件和加入内部源码的位置都有归属；每个迁移包可引用明确回归项；已有失败和未覆盖项单独记录。

边界：不修改调用路径，不调整业务结果。

依赖：QTL-00。完成后可以准备 COR-01。

### COR-01 正式 CMake target 接入

目标：从手工编译 qt-llm 内部源码迁移到正式库目标。

范围与交付：

- 调整 qtllm-bridge 的 CMake 接入和公共/私有包含关系。
- 删除内部源码枚举和相应条件编译拼装。
- 使用公开工具注册兼容面替代 qtllm_builtin_tools_shim。
- 校正 Qt、Sql、Network 等传递依赖和构建开关。
- 明确未提供 qt-llm 时的 CoReader 构建策略。

验收：桥接和应用通过正式 target 构建；不直接加入 qt-llm 的 cpp；不在 qtllm 命名空间重定义内部函数；现有单元测试可链接。

边界：只改变构建和链接方式，不迁移模型调用行为。

依赖：COR-00、QTL-01；还需 QTL-06 提供不会与 shim 冲突的注册兼容面。

### COR-02 模型桥接统一执行路径

目标：让 IQtLlmModelBinding 内部的流式和非流式调用使用同一请求机制。

范围与交付：

- 将 QtLlmModelRequest 映射为统一消息请求与关联信息。
- 将请求句柄的增量、结果、错误、取消和状态映射回现有 DTO 与回调。
- 移除桥接自建的嵌套事件循环、取消轮询和重复配置映射。
- 保留 sendPrompt 等业务便利入口，通过新 invoke 路径转接。
- 保持请求级重试和工作流步骤重试的职责边界。

验收：流式与非流式输出、错误和终态一致；取消不会在后台继续重试；业务调用方无需修改接口；桥接不再维护第二套执行机制。

边界：不修改业务提示词、任务步骤、数据库或 UI。

依赖：COR-01、QTL-02、QTL-04。

### COR-03 调用观察与台账事件迁移

目标：将 qt-llm 基础事件映射到 CoReader 的 Agent Runtime 执行台账。

范围与交付：

- 将模型受理、发送、重试、增量、完成、失败和取消事件适配到现有观察器。
- 保持 taskId、stepId、workflowId 为 CoReader 关联信息。
- 统一线程投递、事件顺序、重复事件和最终状态处理。
- 替换旧钩子时保留必要兼容字段，明确载荷记录和脱敏规则。

验收：一次模型调用形成可关联、无重复终态的台账记录；qt-llm 不解释任务和步骤；禁用详细载荷时不写入提示词正文。

边界：不把 Agent Runtime 事件类型移入 qt-llm，不改变 DAG 或任务状态机。

依赖：COR-02、QTL-03、QTL-04。可与 COR-04、COR-05、COR-06 并行。

### COR-04 BotChat 结构化消息迁移

目标：保留真实对话角色和工具关联，删除将多轮历史拼成单一提示词的协议模拟。

范围与交付：

- 从现有 BotChat 数据库 DTO 生成结构化消息列表。
- 使用统一请求句柄接收正文、reasoning、取消和终态。
- 评估并简化 BotChatService 自建工作线程、取消标志和关闭等待。
- 保留消息落库、文档关联、标题、流式刷新、编辑重发和 UI 行为。
- 将按消息数量裁剪改为明确的上下文预算配置。

验收：模型收到独立角色消息；旧会话可读取；编辑重发与流式显示行为不变；取消和关闭不遗留后台调用。

边界：不迁移 BotChat 数据库，不修改产品提示词和 UI 交互。

依赖：COR-02、QTL-04、QTL-08。可与 COR-03、COR-05、COR-06 并行。

### COR-05 翻译与阅读辅助结构化输出

目标：使用 qt-llm 的输出约束和校验，保留 CoReader 业务模型与回退规则。

范围与交付：

- 为语言路由、翻译和阅读解释定义 CoReader 自有 JSON Schema。
- 将 Schema 作为请求约束，消费解析与校验结果。
- 区分模型失败、JSON 语法错误、Schema 不匹配和业务无效。
- 保留启发式语言检测、业务提示词模板和 fallback capability。
- 根据能力快照决定拒绝、提示约束或产品级降级。

验收：有效结果行为与基线一致；各种失败进入明确回退路径；业务字段和语言规则没有下沉到 qt-llm。

边界：不要求 qt-llm 判断翻译质量，不改变文档处理和阅读结论模型。

依赖：COR-02、QTL-05。可与 COR-03、COR-04、COR-06 并行。

### COR-06 本地模型生命周期迁移

目标：使用 qt-llm 共享运行实例管理，删除 CoReader 的基础运行协调重复代码。

范围与交付：

- 让应用组合根持有或获取明确的本地运行服务实例。
- 将应用目录、模型路径和用户配置映射到公共运行选项。
- 使用状态快照显示可用性与启动计划。
- 在并发、取消、退出和模型切换验证后移除桥接全局互斥。
- 区分 CoReader 启动的服务与外部已有服务。

验收：并发请求不重复启动服务；退出不关闭外部或仍被使用的服务；取消和超时正确；桥接不再维护 llama.cpp 全局锁。

边界：不改变模型安装来源、用户设置产品设计和业务选择策略。

依赖：COR-02、QTL-07。可与 COR-03、COR-04、COR-05 并行。

### COR-07 工具接入与 Agent Runtime 边界迁移

目标：采用公开工具契约，同时保持 Agent Runtime 对工作流和授权的所有权。

范围与交付：

- 通过注册接口接入 CoReader 工具，不修改 qt-llm 内部符号。
- 对 Agent Runtime 使用外部执行模式，映射调用、授权、结果和错误。
- 对不进入 Agent Runtime 的轻量场景，明确是否使用库内有限工具循环。
- 对齐调用 ID、trace、取消、线程要求和副作用重试策略。
- 更新 MCP 客户端接入，不把业务能力误记为已经发布的 MCP Server。

验收：工具调用与结果一一关联；步骤重试仍由 Agent Runtime 管理；拒绝、等待和取消进入现有监视面；无内部符号覆盖。

边界：不将工作流 DAG、业务工具实现或确认 UI 迁入 qt-llm。

依赖：COR-01、COR-03、QTL-06。可在 COR-04 至 COR-06 稳定后独立合入。

### COR-08 跨路径回归与采用验收

目标：证明采用新版基础能力后，CoReader 保持现有代码能力、业务结果和对外行为。

范围与交付：

- 构建 qtllm-bridge、reading-business、agent-runtime、应用和相关测试。
- 回归翻译、阅读辅助、BotChat、调用台账、本地模型和已采用的工具路径。
- 覆盖取消、超时、重试、退出、模型不可用和结构化输出错误。
- 分离离线、受控服务、真实远程模型和真实本地模型证据。
- 检查运行数据、日志脱敏、配置兼容和历史数据读取。

验收：计划内路径有可追溯结论；无业务接口回归；未覆盖项未计为通过；基础库缺陷返回对应 QTL 包处理。

边界：只修复迁移引入的问题，不夹带新业务功能。

依赖：COR-01 至 COR-07 中本次采用范围，以及对应 qt-llm 候选构建。

### COR-09 文档与发布采用收口

目标：使 CoReader 活动文档与实际集成一致，固定可重复的基础库版本关系。

范围与交付：

- 更新 qt-llm 边界、构建、配置、运行诊断和开发接入说明。
- 更新早期 qt-llm 需求提案状态，归档被本方案替代的内容。
- 记录采用的 qt-llm 版本、Qt 版本、工具链和已知限制。
- 提供后续升级的最小回归清单和故障定位入口。

验收：文档不再指导手工源码枚举、shim 或双调用路径；命令和路径与工程一致；规划与已实现能力明确区分。

边界：不在文档收口阶段改变实现。

依赖：COR-08、QTL-10 发布资料。

## 4. CoReader 项目内依赖与并行安排

主迁移链为：

COR-00 → COR-01 → COR-02 → COR-03/COR-04/COR-05/COR-06 → COR-07 → COR-08 → COR-09

| 批次 | 可并行工作包 | 合流条件 |
| --- | --- | --- |
| A | COR-00 | 形成调用和回归基线 |
| B | COR-01 | 正式链接替代旧源码拼装 |
| C | COR-02 | 桥接统一且兼容业务接口 |
| D | COR-03、COR-04、COR-05、COR-06 | 四个集成面分别回归，可独立合入 |
| E | COR-07 | 事件映射与工具公共契约稳定 |
| F | COR-08 | 本次采用范围全部集成 |
| G | COR-09 | 根据验收事实更新文档 |

COR-03 至 COR-06 不互相引用具体实现，可以并行开发。它们共同依赖 COR-02 的薄桥接和统一请求映射。COR-07 依赖事件映射，因为工具调用、授权和结果需要进入现有运行台账。

## 5. 跨项目依赖与协作规则

| CoReader 工作包 | 必需的 qt-llm 稳定成果 | 阻塞条件 |
| --- | --- | --- |
| COR-00 | QTL-00 兼容清单 | 公共接口范围未确认 |
| COR-01 | QTL-01 正式 target；QTL-06 工具注册兼容面 | 仍需编译内部源码或覆盖内部符号 |
| COR-02 | QTL-02 生命周期；QTL-04 请求句柄 | 终态、取消或线程契约未稳定 |
| COR-03 | QTL-03 事件；QTL-04 关联信息 | 事件字段或顺序未稳定 |
| COR-04 | QTL-04 消息请求；QTL-08 上下文策略 | 高级入口不能接收完整消息 |
| COR-05 | QTL-05 结构化输出与能力快照 | Schema 或降级语义未稳定 |
| COR-06 | QTL-07 本地运行服务 | 实例所有权和共享规则未稳定 |
| COR-07 | QTL-06 双工具模式 | 外部执行、授权或结果回传未稳定 |
| COR-08 | 对应 QTL 候选构建 | 依赖能力没有可识别版本或提交 |
| COR-09 | QTL-10 文档与发布资料 | 采用事实和版本尚未固定 |

协作规则：

1. qt-llm 先提供公共头文件、行为说明和最小消费测试，再开始对应 CoReader 迁移。
2. CoReader 发现基础库问题时回报到原 QTL 编号，只保留临时、可删除的兼容适配。
3. 公共契约变化由 qt-llm 记录，业务结果变化由 CoReader 记录。
4. 跨项目验收以明确提交或候选版本为基础，不让两个持续变化的工作区互相验证。
5. COR-08 的结果作为 QTL-10 发布验收的跨项目证据。

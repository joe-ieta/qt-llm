# qt-llm v0.2.12

发布日期：2026-09-23

## 版本定位

`v0.2.12` 在 `v0.2.11` 的组件化和质量门禁基线上，完善请求结果的用量观测、Provider 错误透出和宿主驱动工具循环的集成边界。该版本保持既有公开接口兼容，不改变库的职责范围。

## 主要变化

- `LlmResponse` 新增 `LlmUsage`，报告 Provider 返回的输入、输出、总量、推理和缓存命中 token 用量。
- 流式与非流式 OpenAI-compatible 响应均解析 `usage`；流式请求通过 `stream_options.include_usage` 请求末尾用量块。
- HTTP 4xx/5xx 失败时，`HttpRequestError::message` 优先使用 Provider 响应体中的错误说明，`responseBody` 保留截断后的原始响应体，网络层诊断仅作为回退。
- `QtLLMClient::setToolCallOrchestrator(nullptr)` 可关闭库内工具循环；`RuntimeFacade` 与 `RuntimeRequestHandle` 支持在请求开始前转发该设置，供宿主驱动 External 工具循环。
- DeepSeek 工具续轮始终回传 assistant `reasoning_content` 字段（即使为空），避免 Provider 拒绝续轮请求。
- 本地 HTTP 测试服务器改为读取完整请求后再响应，消除 Qt5 下取消重试测试的偶发失败。
- 发布脚本增加 UTF-8 BOM，兼容 Windows PowerShell 5.1 解析。

## 兼容性

- 未移除或重命名既有公开类、函数、信号和 CMake 目标。
- `setToolCallOrchestrator()` 行为变化：传入 `nullptr` 现在会清除已设置的编排器，此前该调用会被忽略。
- Provider 未返回 usage 时 `LlmUsage` 字段保持为 0，调用方需结合 Provider 行为判断用量是否可用。

- 安装包消费者：20 组。
